About the designer

Hospitality taught me to notice what people need before they have to ask.

I began working in hospitality at 16 and built my career around reading people, protecting their experience, and removing friction without making the service feel intrusive. Disney's standards for safety, courtesy, show, and efficiency became principles I carried into restaurants, guest service, and operational leadership.

Interaction design gives that same instinct a new medium. I combine service judgment, USPS operations leadership, hands-on PC fluency, and formal UX training to design systems that make complicated technology easier to understand and trust.

The problem

PC flexibility makes the user do the integration.

Gaming PCs distribute essential actions across launchers, hardware monitors, settings utilities, media apps, feeds, and Windows itself. The user becomes the integration layer.

RUCA asks a different question: what if the PC communicated readiness immediately, supported controller-first use, and revealed complexity only when it became useful?

Primary audience
Console-comfortable users moving into powerful PC setups
Design goal
Unify high-frequency tasks without hiding truthful system state
Public constraint
Demonstrate behavior without exposing private machine data or native controls

Design process

Turn system complexity into confident decisions.

01

Frame

Mapped the fragmented PC experience into the questions a user is actually trying to answer: Am I ready? What do I want to launch? What is happening? Am I safe? How should RUCA behave?

02

Structure

Converted those questions into five durable worlds with one clear information owner, explicit back paths, and shared input behavior.

03

Prototype

Built responsive, controller-aware browser prototypes and a privacy-safe public demonstration using deterministic local fixtures.

04

Evaluate

Reviewed task paths, focus order, breakpoints, error states, data truthfulness, reduced motion, and rollback evidence across repeated implementation passes.

Research status

This is an independent, evolving case study. Current decisions are grounded in observed console-to-PC friction, iterative prototype evaluation, and technical evidence. Moderated sessions with target users are the next validation step; they are not presented here as completed research.

HOME // Am I ready?

The System Heart carries the machine.

Six live gauges share measured radial geometry around one readiness core. Six conduits visibly carry machine energy inward and outward. Missing sensors remain missing.

  • One Heart and six telemetry channels
  • One geometry owner and one ResizeObserver
  • Measured motion proof, not animation declarations

PLAY // What do I want to launch?

One registry replaced competing app worlds.

Thirty-nine commands use one data owner, one orbit renderer, one selected center, one drawer, and six durable districts. Phone layouts use the same nodes in a compact dock.

39Commands
6Districts
1Registry

LIVE WORLD // What is happening?

Real sources behave like a concierge.

Weather, markets, news, sports, and technology share one observation deck. The active lane owns the hierarchy, wrong-lane content is rejected, and provider failures expose an action path.

  • Five normalized source lanes
  • Live, partial, stale, retrying, and unavailable states
  • No fabricated quotes, scores, forecasts, or headlines

DIAGNOSTICS // Am I safe?

Explanation leads. Raw data follows.

Guardian translates live readings into severity, meaning, first checks, reassurance, serious thresholds, and next actions. Sensor traces and raw ranges remain available for deeper inspection.

CONTROL // How should RUCA behave?

A Workshop, not a settings dump.

The persistent surface holds active profile, presets, and quick controls. Eleven functional systems use progressive drill-down for appearance, atmosphere, controller, audio, source, and location authority.

Outcome

Power without intimidation.

RUCA Command Core now has a coherent product foundation: one shell, five purposeful worlds, truthful machine-state communication, controller-aware interaction, progressive diagnostics, and a control surface built around clear ownership.

The work changed my design practice. I learned to stop treating visual ambition as the starting point, define the user's decision first, reduce competing information owners, and make unavailable states as intentional as successful ones.

The next proof is human: moderated sessions with console-to-PC gamers, physical-controller task testing, and structured iteration from observed behavior.
