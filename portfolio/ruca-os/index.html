RUCA OS

A desktop environment that gives readiness, intent, and system state a clear place to live.

My role
Product direction, information architecture, interaction requirements, visual direction, and implementation review
Product structure
HOME, PLAY, Media Deck, Live World, Diagnostics, and Control

Make the system legible.

A desktop can expose a lot of information without explaining what matters. RUCA gives each surface a responsibility: HOME communicates readiness; PLAY organizes intent; Diagnostics explains condition and availability.

The System Heart anchors the HOME hierarchy. Six surrounding instruments let the user inspect individual channels without losing the overall system context.

Keep context through action.

PLAY groups commands into districts. Opening media expands that task into the Media Deck while preserving the shell and a clear return path.

The interaction model supports inspection before action and reveals deeper controls when the user needs them.

Try the Media Deck →

Missing is meaningful.

Unavailable, stale, and unsupported information have different meanings. RUCA’s state vocabulary keeps those differences visible instead of replacing missing data with zero or implying that an action succeeded.

The browser demo provides sample scenarios. The installed product’s machine telemetry and desktop actions remain local capabilities.

What I designed.

I defined the product structure, visual direction, system-state language, interaction requirements, and acceptance criteria, then used Figma and AI-assisted implementation to iterate on the working interface.

The product remains independent development work. This public demo lets reviewers explore its current design without a local installation.
