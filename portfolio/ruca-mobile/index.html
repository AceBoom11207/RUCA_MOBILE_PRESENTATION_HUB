RUCA OS
Mobile Companion

Preserving the desktop product’s responsibilities while redesigning hierarchy, state, and interaction for a touch-first handheld context.

Not a smaller desktop.

The desktop can display several channels at once. The companion has to answer a different question: what does the user need to see or do from a handheld right now?

The product therefore keeps the same responsibilities while changing the interaction model. Desktop RUCA remains the system and telemetry authority; the companion becomes the touch experience authority.

Five destinations, one continuity model.

HOMESix user-assignable ports mixing telemetry, destinations, commands, and actions.
MEDIANow-playing context, transport, seek, volume, and playback-state feedback without cloning Spotify’s desktop UI.
SYSTEM HEARTSelective machine condition and recovery information from the connected desktop authority.
COMMAND DECKSupported desktop actions organized around explicit availability and confirmation.
DIAGNOSTICSConnection, telemetry freshness, machine identity, and issue state before deeper technical detail.

HOME became configurable instead of generic.

V1 HOME uses six ports because a handheld should surface the responsibilities a user actually reaches for. A port may expose telemetry, open a destination, issue a supported command, or represent an action. Tap performs the primary action. Press-and-hold enters configuration.

Empty, assigned, pressed, connected, stale, unavailable, and failed states are treated as distinct product conditions. A connection failure degrades capability without destroying the user’s layout.

Design truth

The current V1 Figma system is the design authority for this refinement. It should not be mislabeled as an installed-device screenshot. The native Android application is the implementation foundation being reconciled to this UX direction.

MEDIA preserves ownership.

The companion’s media surface is designed around the same playback authority as desktop RUCA. It does not invent a second playback state. The hierarchy prioritizes the current media object, track identity, transport, position, application navigation, and then secondary telemetry.

Controller-era concepts such as back-stack discipline and explicit focus translate into touch as visible pressed, loading, confirmed, unavailable, and failed outcomes.

Design for interruption, not just the happy path.

Connected is not the same as current.

A reachable PC can still return stale or missing telemetry. Connection status and reading freshness therefore remain separate states.

Commands need visible consequences.

Powerful actions require clear target identity, confirmation, and an observable result. Haptics can reinforce feedback but never replace visible state.

User layout survives failure.

Loss of the desktop connection should reduce available capabilities without resetting configured ports or pretending unavailable data is zero.

Evolution, not a greenfield concept.

The Mobile Companion already had a native Android foundation before this V1 design pass. The current work evolves that product through Concept B and Hybrid Cockpit exploration into a production-target system with a consistent shell, five destinations, configurable HOME, connection intelligence, and explicit recovery behavior.

That distinction matters: the portfolio is showing an existing product being redesigned and reconciled, not pretending a Figma frame alone is a shipped application.

What this demonstrates

This project shows cross-device product thinking: preserve meaning and state ownership across desktop and Android while allowing each device to use the hierarchy and interaction grammar that fits its context.
